About the Project

Zimbabwe has faced recurring cholera crises — this system forecasts the next one.

The 2018–2019 Harare outbreak killed 50+ people. The 2023 resurgence spread across 8 provinces. Each time, decision-makers lacked predictive tools that combined epidemiological data with climate, sanitation, and population vulnerability.

CholSurv Zimbabwe is a production-grade, open-source forecasting platform built as an MSc Computer Science research project. It federates data from WHO, Zimbabwe MoHCC, ERA5 climate APIs, and ZimStat into a multi-model ensemble that produces district-level outbreak forecasts at 7, 14, and 30-day horizons.

System Features

Everything a district health officer needs.

📈

Ensemble Forecasting

Three models — Prophet (seasonality), XGBoost (feature importance), LSTM (sequential patterns) — stacked with a ridge regression meta-learner. Achieves 13.7% MAPE, outperforming ARIMA by 56%.

y(t) = g(t) + s(t) + h(t) + βX(t) + ε
🗺️

District Risk Maps

Live choropleth maps across all 15 districts. HIGH / MEDIUM / LOW risk classification updated weekly.

⚗️

What-If Simulator

Model the impact of WASH improvements, OCV campaigns, or rainfall scenarios. Quantified cases averted per intervention.

🌧️

Climate Integration

ERA5 rainfall anomalies, temperature, and humidity as model regressors. Captures the rainfall → cholera lag effect (2–3 weeks).

🔍

SHAP Interpretability

Every forecast explained. SHAP values show which features (rainfall, WASH gap, lag cases) drive each district's risk score.

📶

Low-Bandwidth Mode

Static PNG exports for offline use in district health offices with poor connectivity. Progressive Web App support.

🔗

REST API

FastAPI endpoints for /forecast, /risk-scores, /simulate, and /data. Full OpenAPI 3.0 documentation at /docs.

📊

Power BI Export

Script to push forecast data directly to Power BI via REST API for integration with existing MoHCC reporting infrastructure.

JWT + Token Revocation

HS256 access tokens (30 min) with JTI blacklist for immediate logout. Refresh token rotation (7 days).

✓
TOTP 2FA

Google Authenticator-compatible TOTP via pyotp. Per-user opt-in. Challenge-response login flow.

✓
Role-Based Access Control

Three roles: admin > researcher > viewer. Every endpoint enforces minimum role. Roles stored in JWT claims.

✓
Brute-Force Lockout

5 failed attempts triggers 15-minute account lockout. IP-level rate limiting on /auth/login (10 req/min).

✓
Password Policy

Minimum 12 characters, uppercase, lowercase, digit, and special character required. bcrypt hashing (12 rounds).

✓
Full Audit Trail

Every login, logout, API call, and admin action logged with user, IP, timestamp, and outcome. Queryable via /admin/audit.

✓
Security Headers

HSTS, Content-Security-Policy, X-Frame-Options: DENY, X-Content-Type-Options, Referrer-Policy on every response.

✓
Input Sanitization

SQL injection, XSS, and path traversal patterns blocked at middleware layer before reaching route handlers.

# 1. Login
curl -X POST https://api.cholsurv.zw/auth/login \
  -d "username=researcher&password=Research@2024!"

# 2. Get forecast (use token from step 1)
curl https://api.cholsurv.zw/forecast/Harare?horizon_weeks=4 \
  -H "Authorization: Bearer <access_token>"

# 3. Run a simulation
curl -X POST https://api.cholsurv.zw/simulate \
  -H "Authorization: Bearer <access_token>" \
  -H "Content-Type: application/json" \
  -d '{
    "district": "Harare",
    "wash_improvement_pct": 15,
    "rainfall_change_pct": 10,
    "ocv_coverage_pct": 70
  }'
